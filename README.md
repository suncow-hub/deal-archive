# Deal Archive

M&A·자본시장 딜을 매일 자동으로 모으고, 검증하고, 정리해 아침 브리핑으로 받아보는 개인 학습용 아카이브입니다.
AI(Claude)와 대화하며 설계부터 운영까지 직접 만들었습니다.

사이트: https://suncow-hub.github.io/deal-archive/

> **이 리포와 사이트에 대하여**
> - 금융·M&A를 공부하면서 **개인적인 자료 조사와 학습**을 위해 만든 기록입니다.
> - **포트폴리오로 보여주기 위해 공개**해 두었을 뿐, 정보를 공유하거나 전달할 목적이 아닙니다.
> - 어떤 내용도 **투자 권유나 투자 판단의 참고 자료가 아닙니다.**
> - 딜 노트와 브리핑은 AI가 공개 자료를 바탕으로 정리했으며 오류가 있을 수 있습니다. 각 노트에 출처와 신뢰도(공시 확정 / 보도 기준)를 표시합니다.
> - **소문 탭**은 사실로 확인되지 않은 보도·풍문을 '미확인'으로 표시해 기록하고, 나중에 사실 여부를 대조해 보는 학습용 기록입니다. 운영자는 그 내용이 사실이라고 주장하지 않습니다.
> - 기사 본문은 저장하지 않습니다. 정리한 내용과 원문 링크만 남깁니다.

## 1. 왜 만들었나

업계 뉴스를 꾸준히 읽고, 실제 딜을 구조·가격·자문사 단위로 이해하는 습관을 만들고 싶었습니다. 동시에 AI를 "질문하고 답 받는 도구"가 아니라 **매일 스스로 돌아가는 시스템**으로 써보는 것이 목표였습니다.

처음에 정한 요구사항은 이랬습니다.

- WSJ, 한국경제 등 믿을 만한 소스에서 중요한 딜을 매일 모은다 (딜 최대 10건, 딜 외 뉴스 최대 3건. 최대치일 뿐 할당량이 아님)
- 태그를 눌러 조합 검색이 되게 한다 (예: `한국` + `1조~5조`)
- 같은 딜이 다시 보도되면 새 파일을 만들지 않고 기존 노트를 업데이트하고, 업데이트된 딜을 위로 올린다
- 역할을 나눈 여러 AI 에이전트(발견·검증·정리·관계·브리핑)가 협업한다
- 사용량(토큰)을 아끼고, 평일에만 돌린다
- 아침에 휴대폰으로 핵심 딜 알림을 받는다

## 2. 어떻게 돌아가나

```
 01:30경   ┌─ GitHub Actions: discover ─────────────────────────────┐
 (새벽 작업이│  RSS(WSJ·한경·PR Newswire) + OpenDART 공시 수집         │
  직접 실행) │  → 키워드 필터 → 정정 공시 중복 제거                     │
           │  → Gemini API로 1차 점수 → 5점 미만 탈락                 │
           │  → ECB 기준환율 저장 → candidates/날짜.json              │
           └────────────────────────────────────────────────────────┘
 02:00     ┌─ Claude 예약 작업 (화~토) ──────────────────────────────┐
           │  ① 검증: 공시·보도자료와 대조, 딜당 검색 3회(중요 딜 5회)  │
           │  ② 정리: 템플릿대로 딜 노트 작성·업데이트, 용어집 보강     │
           │  ③ 관계: 회사·PE·자문사 이름 통일, 관련 딜 연결, 태그 검수 │
           │  ④ 브리핑: 아침에 3분 안에 읽을 한 장                     │
           │  → 검사 스크립트 통과 시에만 커밋 → 사이트 재생성          │
           └────────────────────────────────────────────────────────┘
 07:47     Claude 예약 작업: 오늘 브리핑의 한 줄 요약을 휴대폰 알림으로
 14:40경   GitHub Actions: market — 국내 지수·관심 종목 일별 시세 수집
```

| 구성 | 위치 |
|---|---|
| 수집 코드 | `scripts/discover.py`, `scripts/market.py`, `config/discover.yml` |
| Claude 단계 규칙 | `PIPELINE.md`, `agents/verify.md` · `write.md` · `link.md` · `brief.md` |
| 데이터 | `deals/` (딜 노트), `briefings/`, `entities.yml` (회사·기관), `tags.yml`, `glossary.yml`, `rumors.yml`, `market/` |
| 검사·빌드 | `scripts/validate.py`, `scripts/build_site.py` → `docs/` (GitHub Pages) |
| 사이트 | `site/` (정적 HTML·CSS·JS, 서버 없음) |

### 사이트 기능
- **오늘의 브리핑**: 신규 딜, 진행 업데이트, 딜 외 뉴스, 처리 메모
- **딜 아카이브**: 지역·규모·유형·업종·테마·상태 태그 조합 검색 (같은 줄은 '또는', 다른 줄끼리는 '그리고'), 최근 업데이트순, 업데이트 배지
- **딜 노트**: 한 줄 요약, 딜 구조, 밸류에이션, 왜 중요한가, 면접 포인트, 진행 이력, 관련 딜
- **회사·기관**: 회사·PE·자문사별로 등장한 딜 모아보기
- **차트**: 국내 지수·종목(공공데이터 일별 종가)과 해외 티커 검색(TradingView), 홈 상단 지수 띠
- **용어집**: 본문 용어에 점선 밑줄과 풀이, 모르는 단어를 드래그하면 뜻 확인 또는 질문 등록
- **소문(미확인)**: 미확인 보도를 따로 기록하고, 사실로 확인·부인·소멸 여부와 적중률을 추적

## 3. 만들어 온 과정

### 1일차 (10/30): 설계와 첫 실행
- **Notion 대신 GitHub**: 딜 하나를 마크다운 파일 하나로 쌓고 GitHub Pages로 보여주는 구조를 택했습니다. 변경 이력이 남고, 개인 위키(마크다운)와 형식이 같고, 코드·API·자동화를 직접 다뤄볼 수 있기 때문입니다.
- **태그는 자유 입력이 아니라 사전으로**: `#미국`/`#US`/`#USA`가 섞이는 걸 막으려고 `tags.yml`에 대표 값과 별칭을 고정했습니다. 사전에 없는 태그는 자동으로 추가하지 않고 `tag-proposals.md`에 제안만 남겨 사람이 승인합니다.
- **딜 노트 템플릿 확정**: 머리말(검색용 데이터)과 본문(사람이 읽는 부분)을 분리하고, 진행 이력은 줄을 추가만 하게 해서 업데이트 때 중복이 생기지 않게 했습니다.
- **소스 점검**: WSJ·한경·OpenDART·PR Newswire는 공식 RSS/API로 자동 수집이 가능했고, Reuters는 공식 RSS가 없어 제외했습니다. 더벨은 자동 수집을 막고 있어 존중하고, 직접 읽은 기사를 GitHub 이슈로 넣는 **인박스** 방식으로 대신했습니다.
- **채팅 AI 자동화 대신 API**: 처음엔 무료 채팅 AI(GPT·Gemini)를 단계별로 자동 조작하는 안을 검토했지만, 약관·봇 차단·안정성 문제로 버렸습니다. 대신 **발견 단계를 GitHub Actions + Gemini API(무료 구간)로 옮겨** Claude 사용량을 0으로 만들고, Claude는 판단이 필요한 검증·정리·브리핑만 맡게 했습니다.
- **첫 시험 실행**: 후보 68건 → 딜 7건, 딜 외 뉴스 3건. 화면을 직접 띄워 링크 표시 오류, 모든 딜에 업데이트 배지가 붙는 문제, 모바일 필터 길이 문제를 고쳤습니다.

### 2일차 (10/31): 첫 자동 실행에서 드러난 문제 고치기
- **"새 소식 없음" 사건**: GitHub의 예약 실행이 **4시간 반 늦게** 돌아서, 새벽 2시 Claude 작업이 빈 후보로 브리핑을 썼습니다. GitHub 예약 실행을 없애고, **새벽 작업이 시작하면서 수집을 직접 실행하고 끝날 때까지 기다리게** 바꿔 시계를 하나로 만들었습니다.
- **검색 과다**: 첫 실행의 검증 단계가 67번 검색했습니다. 검색 없이 먼저 거르는 단계를 넣고, **딜당 3번 상한**(중요도 8 이상이거나 출처끼리 숫자가 다를 때만 5번)을 두었습니다. 검증된 출처(IR·공시·주요 통신사)만 근거로 쓰고, DART 공시도 검색으로 교차 확인합니다. 다음 실행은 9번(딜 3건 × 3번)으로 줄었습니다.
- **소문 탭 추가**: 공신력이 낮거나 익명 소식통에 기댄 보도도 신호가 될 수 있어서, 딜 아카이브와 분리된 '미확인' 기록을 만들었습니다. 소문을 찾으려고 따로 검색하지는 않습니다.
- **환율 자동화**: 발표일 환율을 매번 검색하던 것을 ECB 기준환율 자동 수집 + 조회 스크립트(`scripts/fx.py`)로 바꿨습니다. 더 정확하고, 검색 예산을 딜 확인에만 쓸 수 있습니다.

### 3일차 (11/1): 차트와 용어집
- **차트**: TradingView 무료 위젯은 한국거래소(KOSPI·KOSDAQ·국내 종목) 데이터를 지원하지 않는다는 걸 확인하고, **국내는 금융위원회 공공데이터 API로 직접 차트**, 해외는 TradingView로 나눴습니다. 국내는 관심 종목과 딜 아카이브에 나온 상장사를 자동으로 추적합니다. 위젯에서 막힌 심볼(미 10년물)은 실제로 시험해 보고 대체 심볼로 바꿨습니다.
- **용어집**: 금융 용어에 익숙하지 않아도 읽을 수 있도록, 아카이브에 나온 용어 42개로 시작해 본문에 밑줄 풀이를 붙였습니다. 모르는 단어를 드래그해서 질문하면 다음 새벽 작업이 풀이를 추가하고, 매일 새 용어를 최대 3개씩 스스로 보강합니다.
- **화면 검증 자동화**: 작업 환경에서 외부 차트 스크립트를 불러올 수 없어서, GitHub Actions에서 실제 브라우저로 배포된 사이트를 캡처하는 점검 워크플로(`site-check`)를 만들어 확인했습니다.

## 4. 점검과 개선

### 보안
| 점검 항목 | 결과 |
|---|---|
| API 키 노출 | 커밋 이력 전체 검사 결과 키 흔적 0건. 키 3개(Gemini, OpenDART, 공공데이터)는 GitHub Secrets에만 있고, 로그에서는 자동으로 가려지며, 결과 파일도 키를 가린 뒤 저장. Claude 단계에는 키가 아예 없음 |
| 자동 실행 권한 | 워크플로는 리포 쓰기 권한만 갖고, 외부 실행 도구는 커밋 해시로 고정. 외부인의 PR로 실행되는 워크플로 없음 |
| **발견 후 수정: 이슈를 통한 지시 주입** | 공개 리포라 누구나 이슈를 만들 수 있는데, 새벽 작업이 모든 이슈를 요청으로 처리하고 있었음. → **리포 소유자가 만든 이슈만** 처리하도록 수정 |
| **발견 후 수정: 링크를 통한 스크립트 실행** | 딜 노트에 `javascript:` 링크가 들어가면 사이트에서 실행될 수 있음을 시험으로 확인. → http(s)·사이트 내부 링크만 남기고 차단 |
| 외부 문서 속 숨은 지시 | 기사·공시·이슈 내용은 "데이터"로만 다루도록 모든 지침에 명시. 검사 스크립트가 형식을 강제하고, Claude 단계엔 키가 없어 피해 범위가 리포로 한정 |
| 개인정보 | 공개 지침 파일의 개인 배경 문구 제거, 커밋 이메일 비공개 설정 권장, 용어집 메모가 공개임을 안내 |

### 법적 리스크 (전문가 자문이 아닌 자체 점검)
| 항목 | 판단과 조치 |
|---|---|
| 자동 수집 | 공식 RSS·API만 사용하고, 자동 수집을 막아둔 사이트(robots.txt)는 수집하지 않음 |
| 저작권 | 기사 본문을 저장하지 않고 사실 요약과 링크만 남김. 후보 파일에 기사 제목이 남는 점은 낮은 수준의 회색 지대로 인지 |
| 데이터 출처 | 공공데이터, ECB 환율, TradingView 출처를 사이트에 표기 |
| 소문 탭 | 상장사 관련 미확인 정보 게시는 명예·신용 훼손이나 풍문 유포 문제와 닿을 수 있어 가장 주의할 부분으로 판단. → 개인 학습·포트폴리오 목적이며 정보 공유·투자 참고용이 아님을 명시, 기업·거래 소문만 다루고 개인 관련 소문 제외, 원 출처 표시, 검색엔진 노출 차단 |
| AI 오류 | 모든 페이지에 "AI 정리, 오류 가능, 투자 권유 아님" 표기. 노트마다 신뢰도(공시 확정/보도 기준) 표시 |

### 효율
- 가장 많이 읽는 발견 단계를 무료 구간의 GitHub Actions와 Gemini로 옮겨 Claude 사용량에서 제외
- 검색 없이 먼저 거르기와 딜당 검색 상한으로 검증 비용 절감 (67회 → 9회)
- 같은 날 재실행 시 수집 중복 실행 방지, 사이트 빌드를 결정적으로 만들어 자동 빌드끼리 충돌하지 않게 함
- 시세 수집 실패는 다음 날 브리핑 처리 메모에 표시
