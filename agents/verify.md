# ① 검증 에이전트

입력: `candidates/<날짜>.json`, `work/inbox.json`(있으면), `work/index.txt`(기존 딜 목록), `tags.yml`, `rumors.yml`(기존 소문)
출력: `work/verified.json`

## 할 일

0. **원칙**: 검색은 딜 하나당 기본 3번, 중요한 딜은 최대 5번이다 (4번 참고). 환율은 검색하지 않는다 (7번). 전체 검색 횟수를 `notes`에 "검색 N회"로 남긴다.
0-1. **보조 발견 (검색 최대 3번)**: 피드로는 잘 안 잡히는 구간을 웹 검색으로 보완한다. 아래 중 오늘 필요한 것을 골라 **합계 3번 이내**로 검색한다 (지난 30시간 이내 보도만).
   - 아시아(싱가포르·홍콩·일본·동남아) PE·M&A 딜
   - 글로벌 대형 딜 (Reuters·Bloomberg 단독 보도 등)
   - 국내 매각 절차 소식 (예비입찰, 본입찰, 우선협상대상자 선정)
   후보 파일에 이미 있는 딜은 빼고, 새로 찾은 것은 **최대 5개**까지 후보에 더한다. 이후 검증 규칙은 다른 후보와 똑같다. 이 3번은 아래 딜별 검색 상한과 따로 센다. `notes`에 "보조 발견 검색 N회, 추가 후보 M개"를 남긴다.
1. **딜 후보 묶기**: 같은 거래를 다룬 후보(예: 공시 2건, 기사 2건)는 하나로 묶는다.
2. **기존 딜 확인**: `work/index.txt`에 이미 있는 거래면 `existing`에 그 파일 경로를 적는다. 새 소식(상태 변화, 금액 확정, 승인 등)이 없으면 버린다.
3. **1차 선별 (검색 없이)**: 후보 제목·점수 사유·`dart_details`만 보고 아래 5번 기준으로 중요도를 먼저 매긴다. 5점 이하로 보이는 후보는 검색하지 않고 바로 `dropped`로 보낸다. 검색은 남은 후보에만 쓴다.
4. **사실 확인 (검색 상한 엄수)**: 남은 딜마다 당사자, 금액, 지분, 구조, 자문사, 상태, 발표일을 확인한다.
   - **딜 하나당 검색·페이지 열기(WebSearch + WebFetch 합산)는 기본 3번.** 3번 안에 확인이 안 되면 거기서 멈추고, 확인된 것만 쓰고 `보도 기준`으로 둔다. 몇 번 썼는지 딜마다 세면서 진행한다.
   - **최대 5번까지 늘릴 수 있는 경우**는 둘뿐이다: (a) 1차 선별 중요도가 8 이상인 딜, (b) 출처끼리 핵심 숫자(금액·지분·가격)가 서로 다를 때. 늘렸다면 `notes`에 딜 이름과 이유를 적는다.
   - **DART 공시도 검색으로 교차 확인한다.** `dart_details`는 출발점일 뿐이며 정정·누락이 있을 수 있다. 공시 숫자와 보도·보도자료 숫자가 다르면 둘 다 `notes`에 적는다.
   - **검색은 검증된 출처를 겨냥한다.** 우선순위:
     1) 회사 IR·보도자료, 거래소 공시(DART, SEC, HKEX 등), 규제기관 발표
     2) 주요 통신사·경제지: Reuters, Bloomberg, WSJ, FT, 연합뉴스, 한국경제, 매일경제, 더벨, 딜사이트
     블로그·커뮤니티·출처 불명 사이트·AI 요약 사이트는 근거로 쓰지 않는다.
   - 유료 기사(WSJ 등)와 dart.fss.or.kr 웹페이지는 열지 않는다. 검색 결과의 제목·요약과 다른 공개 자료로 확인한다.
   - 공시·보도자료로 확인되면 `공시 확정`, 언론 보도로만 확인되면 `보도 기준`.
   - 확인이 안 되는 숫자는 적지 않는다. 추측하지 않는다.
5. **중요도 판단 (1~10)**: 다음을 볼 때 높게.
   - 규모가 큼 (대략 1조 원 이상이면 높게, 1천억 미만이면 낮게)
   - 한국 시장·한국 기업이 걸려 있음
   - 업계 흐름을 보여줌 (업종 첫 사례, 대형 PE 엑시트, 지배구조 개편 등)
   - 소규모 IB·부티크·외국계 IB가 자문으로 참여
   - 계열사 간 소규모 합병, 비상장 소기업 간 거래, 단순 루머 반복은 낮게
6. **선택**: 중요도 6 이상만 남기고, 그중 상위 **최대 10건**. 6 미만은 `dropped`로.
   인박스 기사는 본인이 고른 것이니 중요도 5 이상이면 남긴다.
7. **환율**: 외화 딜은 발표일 기준 원화 환산값을 구한다. **검색하지 말고** `python3 scripts/fx.py <발표일> <통화> <금액>` 으로 구한다 (ECB 기준환율, 휴일이면 직전 영업일). `fx_note`에는 "ECB 기준환율 YYYY-MM-DD, 1 USD = N원"처럼 적는다. 공시에 회사가 정한 환율이 있으면 그것을 우선한다.
8. **시장 소문 분리**: 아래에 해당하는 것은 버리지 말고 `rumors`로 보낸다 (하루 **최대 5건**, 최대치일 뿐 채울 필요 없음).
   - 사실이라면 중요도 6 이상일 딜인데, 검증된 출처(4번 우선순위)로 확인되지 않은 것
   - "검토 중", "추진설", "인수설", "협상 중(익명 소식통)"처럼 아직 공식화되지 않은 보도
   - 4번 확인 과정에서 공신력 낮은 출처(블로그, 커뮤니티, 출처 불명 사이트 등)에서 우연히 본 딜 관련 단서
   - **딜 노트 vs 소문 구분**: 검증된 출처가 거래 체결·발표·공식 추진(우선협상대상자 선정, 공개매수 공시 등)을 사실로 보도했으면 딜 노트(`보도 기준`)다. 검증된 출처라도 "협상 중·검토 중"을 익명 소식통에 기대 전하는 단계이거나, 공신력 낮은 출처에만 있는 내용이면 소문이다.
   - 소문을 위해 **따로 검색하지 않는다.** 이미 본 후보·검색 결과에서만 고른다.
   - 기업·거래에 관한 소문만. 특정 개인의 사생활·혐의·건강 등에 관한 소문은 넣지 않는다.
   - 기존 소문(`rumors.yml`)과 같은 내용이면 새로 만들지 말고 `existing_rumor`에 그 id를 적는다.
9. **딜 외 뉴스**: `kind: macro` 후보 중 같은 사건은 하나로 묶고, 금리·환율·규제·국제정치처럼 딜 시장에 영향이 큰 것 **최대 3건**을 고른다. 본문은 열지 않는다. 제목과 점수 사유로 판단한다.

## 출력 형식 (`work/verified.json`)

```json
{
  "date": "YYYY-MM-DD",
  "deals": [
    {
      "key": "doordash-instacart",
      "existing": null,
      "inbox_issue": null,
      "headline": "DoorDash, Instacart 170억 달러에 인수",
      "parties": {"인수자": ["DoorDash"], "대상": ["Instacart"], "매도자": []},
      "amount_original": "USD 17B",
      "amount_krw": "약 24.4조 원",
      "fx_note": "ECB 기준환율 2026-10-29, 1 USD = 1,337.29원",
      "stake": "100%",
      "structure": "현금+주식, 주당 ○달러",
      "valuation": "비공개",
      "advisors": {"재무": [], "법률": []},
      "status": "계약 체결",
      "confidence": "공시 확정",
      "announced": "YYYY-MM-DD",
      "region": ["미국"],
      "sector": ["IT·소프트웨어·플랫폼"],
      "type": ["경영권 인수"],
      "theme": [],
      "sources": ["https://..."],
      "why": "왜 중요한지 1~2문장",

  ],
  "rumors": [
    {
      "existing_rumor": null,
      "title": "○○, △△ 인수 검토설",

  ],

```
